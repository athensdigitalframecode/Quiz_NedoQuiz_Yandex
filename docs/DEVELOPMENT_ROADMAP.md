### R-16. Лидерборды на актуальном API — ✅ 12.11
Код вызывал `lb.setScore`/`lb.getEntries` у объекта `ysdk.getLeaderboards()` (устарел; у него методы `setLeaderboardScore`/`getLeaderboardEntries`), поэтому на настоящем SDK ни отправка, ни показ не работали. Теперь `ysdk.leaderboards`; отправляется личный рекорд, а не последний счёт; после входа рекорды отправляются с паузой 1,1 с (лимит `setScore` — 1 запрос в секунду).

### R-17. Потребление покупки только после сохранения — ✅ 12.11
`consumePurchase` вызывается, только если `player.setData` прошёл; иначе покупка остаётся и обрабатывается при следующем запуске (повторная выдача исключена токеном в `S.tok`).

### R-01. Заменить `confirm()` на окно внутри игры — ✅ сделано 12.11 (локально)
- **Приоритет:** P0
- **Что:** в обработчике `[data-leave]` (выход из «Сам с собой») и в `chcancel` (отмена вызова) вместо `confirm()` показывать модальное окно игры с кнопками «Завершить» и «Продолжить». Поиск: `grep -n "confirm(" index.html`.
- **Зачем:** в iframe Яндекса системные окна могут не открываться. Тогда `confirm` вернёт `false`, и игрок не сможет выйти из партии. Плюс это выглядит чужеродно.
- **Затрагивает:** выход из партии, отмену вызова, тест `t18` (там подменяется `window.confirm`).
- **Результат:** выход работает без системных окон и выглядит как остальной интерфейс.
- **Проверка:** обновить `t18` на нажатие кнопок окна; проверить выход на 0, 1 и 5 ответах; убедиться, что `confirm(` в коде больше нет.

- **Приоритет:** P1
- **Что:**
  - сейчас `stats/*` и `games/*` может записать любой вошедший игрок;
  - вариант: перенести начисление рейтинга в RPC с `SECURITY DEFINER`, который проверяет, что вызывающий — участник партии `games/<code>` и что результат взят из документа партии; прямую запись в `stats` закрыть;
