## Главное правило
Развивать существующую игру, а не переписывать её. Не удалять работающие режимы, данные и сохранения. Не менять баланс и коммерческие условия без обоснования и согласия владельца.

## Общение
- Отвечать по-русски, коротко, без длинных пересказов сделанного.

## Git и выкладка
- Коммитить и пушить только после слова владельца «загрузи» (или явной просьбы). Перед пушем сделать `git fetch` и проверить, нет ли чужих коммитов.
- В конце сообщения коммита — строки соавторства, которые задаёт среда.
- Никогда не класть в код токены: Telegram, GitHub PAT, секретные ключи. Публичный ключ Supabase (`sb_publishable_…`) в коде допустим.
- Не публиковать игру в Яндекс Играх, не запускать платную рекламу и не подключать платные сервисы без явного согласия.

## Как устроен код
- Вся игра — один файл `index.html`, примерно 2,4 МБ и 5 300 строк: HTML, CSS и чистый JS без сборщика. Банк вопросов `const BANK=[...]` — одна строка около 1,4 МБ.
- **Не читать `index.html` целиком.** Искать через `grep -n`, читать диапазонами строк. Строку `BANK` не выводить.
- Правки банка вопросов делать скриптом через `json.JSONDecoder().raw_decode` — обратная сериализация совпадает побайтно. Перед массовой правкой сделать резервную копию.
- После любой правки `index.html`, `supabase.js` или `fonts/` запустить `python dev/stamp.py .`: он обновляет BUILD в `index.html`, `V` в `sw.js` и `version.json`. Без этого игроки получат старую версию.
- ZIP для Яндекса — только `python dev/build_zip.py` (результат в `dist/`).
- Яндекс SDK: лидерборды через `ysdk.leaderboards` (не `getLeaderboards()`), покупку потреблять только после успешного `player.setData`.
- Для подтверждений использовать окно игры `askYes(заголовок, текст, «да», «нет»)`, никогда `confirm()`/`alert()`/`prompt()`.
- События воронки писать через `qm(ключ)` / `qmOnce(ключ, id_партии)`. Описание ключей — в `dev/sql/funnel.sql`.
- Видимые игроку изменения записывать в `UPDATES` (новая запись сверху, `id:"uNN"`), если владелец не сказал «не пиши в обновления».

## Проверки
- Автотесты: `python dev/tests/run_all.py` (или по одному `dev/tests/t_*.py`). Playwright (`pip install playwright`) + системный Chrome (переменная `CHROME`), без скачивания браузера. Подставные SDK (`mock_sdk.js`) и база в памяти (`fake_supabase.js`); все внешние запросы обрываются — рабочая база не трогается. Перед коммитом — ни одного FAIL.
- Тесты не проверяют настоящие SDK, покупки, рекламу, лидерборды и мультиплеер в реальном времени — говорить об этом прямо.
- Локальная проверка: `python dev/serve.py 8792 --mock` (подставной SDK `dev/tests/mock_sdk.js`, вызовы пишутся в `window.__yg`; `?failsave` — сбой облачного сохранения) или без `--mock` — как обычный браузер. **Подставной SDK работает с рабочей базой Supabase** — не запускать партии основного режима без нужды.
- Новые возможности сопровождать тестом в `dev/tests/t_*.py` через `harness.py`.
- Тесты не проверяют реальные покупки, лидерборды, рекламу и мультиплеер через Supabase. Об этом нужно прямо говорить, когда что-то «готово».

## Принципы продукта, которые нельзя нарушать
- За реальные деньги не продаются очки, рейтинг, время на ответ и подсказки. Покупки дают только оформление, звёзды (тратятся только на оформление) и отключение полноэкранной рекламы.
- Реклама только в логических паузах: не посреди вопроса и не во время командной игры. Ролик за награду всегда добровольный.
- Игровые очки, внутренний рейтинг (1000 и выше, звания) и лидерборды Яндекса — разные сущности, их нельзя смешивать.
- Не делать подписку, лутбоксы за деньги, штрафы за пропуск дня и таймеры «предложение истекает».
- Требования Яндекса: нет внешних ссылок, нет обязательной регистрации вне Яндекс ID, есть гостевая игра с сохранением прогресса, звук и игра ставятся на паузу во время рекламы.
- При добавлении вопросов сначала проверять дубли.
- Тема «Что? Где? Когда?» (31) не попадает в платные функции, пока не подтверждена лицензия. «Аниме» (22) скрыто через `HID`.
