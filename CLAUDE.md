# CLAUDE.md — «Квиз или Недоквиз»

Постоянные правила для Claude Code. Это расширенная версия прежнего `CLAUDE.md` репозитория (копия: `docs/archive/CLAUDE.repo-2026-11-25.md`): из него ничего не убрано, добавлены правила из переписки в claude.ai.

Читать по задаче, не всё подряд:
- `PROJECT.md` — что за игра, механики, сценарии, дизайн.
- `DECISIONS.md` — решения, отвергнутые идеи, ошибки, которые нельзя повторять.
- `ROADMAP.md` — сделано / не сделано / баги / планы.
- `docs/IMPLEMENTATION_PROGRESS.md` — **читать первым в новой сессии**: ход текущих этапов.
- `docs/PROJECT_HANDOFF.md` (якоря кода, данные), `docs/ARCHITECTURE.md`, `docs/KNOWN_ISSUES.md`, `docs/DEVELOPMENT_ROADMAP.md`, `docs/DEVELOPMENT_LOG.md`, `docs/PLATFORM_MATRIX.md`, `docs/PRODUCT_BRIEF.md`, `docs/MASTER_IMPROVEMENT_PLAN.md` (мастер-план, 87 КБ — читать разделами).

## Главное правило
Развивать существующую игру, а не переписывать её. Не удалять работающие режимы, данные и сохранения. Не менять дизайн, баланс и коммерческие условия без обоснования и согласия владельца. Сначала P0 и P1.

## Общение с владельцем
- По-русски, коротко, без пересказа сделанного.
- Не спрашивать то, что можно выяснить из кода, git или базы.
- Отделять проверенное (код, тест, запрос к базе) от предположений.
- Файлы читать диапазонами строк. Сабагентов не запускать.
- Не публиковать игру, не запускать платную рекламу, не подключать платные сервисы и не тратить деньги без явного согласия.

## Git и выкладка
- Коммитить и пушить **только после слова «загрузи»** (или явной просьбы). Перед пушем `git fetch` и проверить чужие коммиты: репозиторий могли менять из другого чата.
- В конце сообщения коммита — строки соавторства, которые задаёт среда.
- Никогда не класть в код токены: Telegram, GitHub PAT, секретные ключи. Публичный ключ Supabase (`sb_publishable_…`) в коде допустим.
- Миграции базы — только с согласия владельца, перед ними резервная копия (`select * into docs_backup_YYYYMMDD from docs`), проверка SQL-сценарием в транзакции с откатом.

## Как устроен код
- Вся игра — один файл `index.html` (~2,6 МБ, ~5 300 строк): HTML, CSS, чистый JS без сборщика. Банк `const BANK=[...]` — одна строка ~1,4 МБ.
- **Не читать `index.html` целиком.** `grep -n` по якорю (таблица якорей — `docs/PROJECT_HANDOFF.md`, раздел 2), затем диапазон строк. Строку `BANK` не выводить.
- Правки банка — скриптом через `json.JSONDecoder().raw_decode` (обратная сериализация совпадает побайтно). Перед массовой правкой — резервная копия. **Порядок `BANK` не менять и вопросы не удалять:** индексы используются в `seen`, `games.qs`, квизе и вопросе дня. Править на месте.
- После любой правки `index.html`, `supabase.js`, `gp-*.js` или `fonts/` — `python dev/stamp.py .` (BUILD в `index.html`, `V` в `sw.js`, `version.json`). Без этого игроки получат старую версию.
- ZIP: `python dev/build_zip.py` (Яндекс) или `python dev/build_zip.py --gp` (GamePush) → `dist/`.
- Яндекс SDK: лидерборды через `ysdk.leaderboards` (не `getLeaderboards()`), `setScore` не чаще 1 раза в секунду; покупку потреблять только после успешного `player.setData`.
- Подтверждения — окно игры `askYes(заголовок, текст, «да», «нет»)`, никогда `confirm()`/`alert()`/`prompt()`.
- События воронки — `qm(ключ)` / `qmOnce(ключ, id_партии)`; описание ключей — `dev/sql/funnel.sql`.
- Облачное сохранение `S`: новые поля только добавлять, `merge` должен их понимать.
- Видимые игроку изменения — запись в `UPDATES` (новая сверху, `id:"uNN"`, последняя сейчас `u98`), если владелец не сказал «не пиши в обновления».

- Автотесты: `python dev/tests/run_all.py` (или `dev/tests/t_*.py` по одному). Playwright + системный Chrome (переменная `CHROME`), без скачивания браузера. Подставные SDK (`mock_sdk.js`, `mock_gp.js`) и база в памяти (`fake_supabase.js`); внешние запросы обрываются. Перед коммитом — ни одного FAIL.
- Новые возможности — с тестом `dev/tests/t_*.py` через `harness.py`.
- Локально: `python dev/serve.py 8792 --mock`. **Подставной SDK работает с рабочей базой Supabase** — не запускать партии основного режима без нужды.
- Тесты не проверяют настоящие SDK, покупки, рекламу, лидерборды, `payload`, мультиплеер в реальном времени и телефон. Говорить об этом прямо, когда что-то «готово».

## Принципы продукта, которые нельзя нарушать
- За реальные деньги не продаются очки, рейтинг, время на ответ и подсказки. Покупки дают только оформление, звёзды (тратятся только на оформление) и отключение полноэкранной рекламы.
- Реклама только в логических паузах: не посреди вопроса и не во время командной игры. Ролик за награду всегда добровольный.
- Игровые очки, внутренний рейтинг (старт 1000, звания) и лидерборды платформы — разные сущности, не смешивать.
- Нет подписки, лутбоксов за деньги, штрафов за пропуск дня, таймеров «предложение истекает».
- Требования Яндекса: нет внешних ссылок, нет обязательной регистрации вне Яндекс ID, гостевая игра с сохранением, звук и игра на паузе во время рекламы.
- **Перед добавлением вопросов — проверить дубли по смыслу**, а не только по тексту: повторы бывают в другой формулировке (дни рождения, «Я лжец», ±20 % цены, Монти Холл, нули в 100!, квадраты на доске, стрелки часов). Вопросы умные, но простые, ответ однозначный, факты и вычисления проверять. Формат элемента `BANK`: `c` тема, `d` e/m/h, `q`, `a` верный, `w` 3 неверных, `e` пояснение. Новые вопросы показывать владельцу и добавлять только после «да».
- Картинки для вопросов — только CC0 и общественное достояние; без платных данных и лицензий NC.
- Тема «Что? Где? Когда?» (31) не попадает в платные функции, пока не подтверждена лицензия. Номер 22 — удалённая тема: не использовать.
- Детские темы не попадают в «Микс тем», у них отдельный рейтинг. По названиям детские — 27–29; в коде `isKid=c=>c>=27&&c<=32` (захватывает и 30–32) — не трогать без проверки, см. `ROADMAP.md`.
- Режимы для компании в этой версии скрыты по решению владельца (13.11) — не включать без решения.
